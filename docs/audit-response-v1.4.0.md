# Response to the 1.3.1 app review

Target release: **1.4.0 / version code 11**. Review date: **23 September 2026**.

This document tracks the response to *The Spencerian Desk 1.3.1 — Security and quality review of the Android app (APK)*, supplied by the user on 23 September 2026. The reviewed APK has SHA-256 `989db6077220276450fae0b40a754c9fb37b08afc7122869386739396791f594`. It is the same 1.3.1 / code 10 release retained in this repository.

The 1.4.0 source and signed APK implement the changes marked **Implemented** below. The release passed 193 automated checks and package verification; see [the release verification](verification.md) for the exact evidence and limits. No physical Android device, emulator, or real-browser rendering pass was completed. The manual acceptance matrix remains pending and must not be read as a device pass.

## What the review establishes

The reviewer inspected the APK and ran its web assets in a desktop Chromium test environment. The report gives useful browser measurements for repeated whole-state saves, large exports, navigation focus, headings, and icon appearance. Those measurements describe the reviewer's environment; they are not performance measurements for the updated app or an Android phone.

The report did **not** test a physical Android device or an Android emulator. Its system-bar illustration is explicitly a simulation. Insets, keyboard behavior, activity recreation, process death, Android file pickers, predictive Back, and recent-app previews therefore need native acceptance testing. Source changes and JVM/DOM tests can cover their implementation boundaries without proving the complete device behavior.

The review's statement that no serious security holes were found is a result of that review, not a guarantee that the app has no vulnerabilities.

## Data compatibility and safety checks

The release must preserve package `com.royal.spencerianlab`, the existing signing certificate, the `SpencerianLab` database name, and all stable lesson IDs. Version code 11 must be greater than 1.3.1's code 10. A development or CI key cannot replace the maintainer's signing identity for an installed-app update.

Database version 2 is an internal storage change. Existing schema-1 progress and JSON backups remain accepted after validation. Splitting images out of a valid legacy state must occur atomically: failed migration must leave the old record usable. Invalid legacy data must remain available to the established recovery path rather than being overwritten with defaults.

New streaming backups must be complete before export is reported successful. Restore must reject malformed metadata, duplicate or missing drawing records, invalid image payloads, excessive per-record sizes, unknown record kinds, and truncated input. Until the user confirms a fully validated import and its final database transaction succeeds, current progress must remain intact. Canceled or interrupted imports must not become live progress and should be cleaned up on the next open.

The journal's existing 2,000-session and 1,000-concept limits continue to apply unless explicitly changed and tested. A streamed backup avoids repeatedly copying the whole journal through the bridge; it cannot guarantee sufficient temporary disk space, destination capacity, or unlimited document-provider throughput.

Reference photographs remain transient. They are excluded from progress, draft recovery, and backups. They are sent to an AI provider only after the existing explicit native confirmation. Keystore-protected provider credentials remain outside JavaScript state and backup files. Erasing the app's local data cannot delete a user's exported backups or recall provider requests already sent.

## Scope retained

This work addresses defects and practical safeguards in the existing offline penmanship app. It does not claim OCR accuracy, teacher-certified letterforms, signature uniqueness, handwriting speed, legal authenticity, universal stroke-order recovery from a still image, or improved S Pen pressure/palm rejection without device evidence. It does not introduce cloud synchronization, remote analytics, automatic AI requests, translations, a new visual theme, or a Google Play publication.
